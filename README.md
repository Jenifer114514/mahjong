# PeerJS 対戦リーチ麻雀

ブラウザだけで遊べる **3人／4人対戦のリーチ麻雀** です。PeerJS（WebRTC）によるP2P通信のオンライン対戦と、**CPUを相手にしたソロ対局**の両方に対応しています。スマホは横画面に最適化されたレイアウトで遊べます。

- 🎮 すぐ遊ぶ: https://jenifer114514.github.io/mahjong/
- 📝 実装の記録（Notion）: 段階ごとの仕様・プロンプト・実装ログを管理

## 遊び方

### CPUとソロで遊ぶ（通信なし）
1. トップの「**いますぐCPUと対局（通信なし）**」を押す
2. 既定は 4人麻雀・東風戦・CPU 3体。人数・長さ・ローカルルール・CPU数は上のカードで変更できます
3. 手番になったら、切る牌をタップ。鳴き・ロンの機会があれば操作バーが表示されます

### オンラインで対戦する
- **ホスト**: 部屋の設定（人数・長さ・ローカルルール・CPU数）を決めて「部屋を作成」→ 表示された**部屋コード**か**招待URL**を共有
- **ゲスト**: 「部屋に参加する」にコードを入力、または招待URLを開く
- 規定人数（人間＋CPU）が揃うと自動で開局します

### 操作方法
| 操作 | 方法 |
| --- | --- |
| 打牌 | 手牌／ツモ牌をタップ |
| リーチ | 「リーチ」→ ハイライトされた牌をタップ |
| ツモ和了 | 「ツモ和了」 |
| 鳴き・ロン | 応答バーの「ロン」「ポン」「チー」「大明槓」（時間切れは自動スルー） |
| 槓・抜北・九種九牌 | 手番アクションの各ボタン |
| 自動ツモ切り | リーチ中に ON/OFF を切り替え |

> スマホは**横向き**にすると雀卓＋右サイドパネル（スコア／捨て牌／局情報）の2カラム表示になり快適です。縦向きでは卓を縦に積んだレイアウトに切り替わります。

## 対応ルール・実装済み機能

**対局進行**
- 3人麻雀（2〜8萬抜き・108枚・35,000点）／4人麻雀（136枚・25,000点）
- 東風戦・半荘戦、起家からの席順シャッフルとCSPRNGでの山牌生成
- 本場・連荘／親流れ、オーラス判定、トビ終了、終局時の残供託をトップへ加算

**和了・点数**
- 一般役・状況役、ドラ／裏ドラ／カンドラ、符計算、満貫〜役満・ダブル役満、数え役満
- ツモ／ロン、ダブロン（頭ハネ設定可）、本場加算、供託リーチ棒の受け取り

**鳴き・槓**
- ポン・チー・大明槓・加槓・暗槓、喰い替え禁止、槍槓、嶺上牌補充
- 3人麻雀の抜き北（ドラ扱い）、四槓散了

**リーチ・流局**
- リーチ／ダブルリーチ、一発、リーチ後の暗槓可否判定、リーチ後の自動ツモ切り
- 荒牌平局のテンパイ／ノーテン罰符（自動判定・テンパイ手牌の開示）
- 途中流局: 九種九牌・四風連打・四家立直・四槓散了・三家和
- 海底摸月・河底撈魚・嶺上開花・天和・地和

**情報隠蔽**
- サーバ（ホスト）は各プレイヤーごとに `StateView` を生成し、他家の手牌・山牌・未公開ドラ・他家の鳴き候補を一切送信しません

**CPU（第5段階）**
- 向聴数＋受け入れ枚数（見えている牌は除外）で打牌を選択
- リーチ／ツモ和了／暗槓／加槓／抜北／九種九牌、鳴き（ポン・チー・大明槓）、ロンは常に優先
- 判断材料は人間と同じ情報量（`StateView` のみ）で、他家の手牌や山牌は参照しません

**ローカルルール設定**
- トビ終了、喰いタン、後付け、本場加算、3人麻雀のツモ損
- ダブロン／喰い替え禁止／応答タイムアウト／1局のカン上限などは `RuleConfig` で差し替え可能

## 技術スタック

- **TypeScript** + **Vite**
- **PeerJS**（WebRTC データチャネル、STUN のみ／TURN なし）
- 状態管理は純粋関数の reducer（`(state, action) => state`）
- テストは **Vitest**（エンジン・通信プロトコル・UI描画・CPU思考）
- 配信は GitHub Pages（`main` へのマージで自動デプロイ）

## 開発

```bash
npm install     # 依存関係のインストール
npm run dev     # 開発サーバー (http://localhost:5173)
npm test        # テスト（Vitest）
npm run build   # 型チェック + 本番ビルド
npm run preview # ビルド成果物のプレビュー
```

## 既知の制限

- 赤ドラは未対応（型に `isRed` の枠のみ用意）
- アガリ止め／オーラスでの打ち切りは未実装
- TURN サーバを用意していないため、NAT の厳しい環境では P2P 接続に失敗することがあります
- CPU の強さは1段階のみ（難易度設定は未実装）
